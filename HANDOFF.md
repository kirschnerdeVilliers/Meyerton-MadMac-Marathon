# Handoff — Midvaal MadMac 2026 site

Orientation doc for starting a new Claude Code session on this project. The site is fully built,
live, and the CMS works end to end — this isn't recovering from an interrupted task, it's a

## What this is

A one-page marketing/entry-conversion site for a South African road race (Midvaal MadMac, Meyerton
Athletics Club, 4 October 2026) — its only job is converting visitors into Race Pass entries.
Static site, custom-built lightweight generator, plus a real git-based CMS for non-technical
editors.

## Architecture, briefly (README.md has the full detail — this is just the map)

- `data/race-config.json` — all editable content, one file
- `tools/render.py` — the static-site generator (Python stdlib only, zero dependencies, zero
  build tooling — deploy is just "the folder is the site")
- `tools/build-routes.py` — GPX → route JSON + elevation SVGs; only re-run if the GPX files
  themselves change, not for routine content edits
- `admin/config.yml` + `admin/index.html` — the CMS schema and shell
- `.github/workflows/build-deploy.yml` — auto rebuild + deploy on a content-affecting push

## Things worth knowing before touching anything

1. **Never hand-edit `index.html`** — it's a generated build artifact. Edit
   `data/race-config.json` (by hand or via `/admin/`), then run `python3 tools/render.py`.
2. **`race-config.json` may contain `""` instead of `null`, and prize-table numbers may be
   strings** — this is normal CMS behaviour (Sveltia saves blanks and text-field numbers this way),
   already handled permanently by `normalize_blanks()` / `prize_cell()` in `render.py`. Don't
   "fix" it as a data bug if you see it.
3. **GitHub Pages build source is "GitHub Actions"**, not "Deploy from branch" — deliberate, part
   of making the CMS work. Don't switch it back.
4. **CMS auth depends on a Cloudflare Worker** (`sveltia-cms-auth`) that isn't in this repo — its
   source was cloned to `/tmp` during setup and may not have survived a reboot. If login breaks,
   check the GitHub OAuth App's Client ID (github.com/settings/developers) matches
   `GITHUB_CLIENT_ID` on that Worker; they're independent and nothing keeps them in sync.
5. `SITE_URL` in `render.py` is `https://midvaalmadmac.co.za` — the real, purchased domain, now
   wired up as a GitHub Pages custom domain (root `CNAME` file + the repo's Pages setting). It's
   what canonical URLs, OG tags and JSON-LD all derive from, so if the domain ever changes, update
   this and the `CNAME` file together.
